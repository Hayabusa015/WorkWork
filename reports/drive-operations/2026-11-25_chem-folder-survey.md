## 6. Proposed changes

Rules on renaming and retiring, as they apply here:
- **Rename** is allowed when deterministic. Log the ID, prior name and prior parent first
  (`DRIVE_ARCHITECTURE.md` §3, `NAMING.md` §5). **Never batch-rename without confirmation.** Renaming
  a folder keeps its ID and every file inside it, so contents do not block a rename. No rename is
  needed today: every unit and section name matches.
- **Retired-code folders.** The standard has no general rule. The only guidance is in the
  SHULL-CHG-0036 and SHULL-CHG-0054 records: such a folder "can be left as a marker or trashed with
  his approval and a pre-mutation log". Trashing needs Matt's approval in every case (§3). A
  retired-code folder **that holds files** cannot simply be trashed. Each file would first need a
  reparent to the section it now belongs to, and choosing that section is a content call. That
  makes it non-deterministic, so Matt decides. Codes that **changed meaning** (U6, U7, U11, U12) are
  different: a folder there would be renamed to the new title before anything is filed (SHULL-CHG-0099
  risk note). On Drive today the only retired-code folder is 01.4, and it is empty. No folder has a
  changed-meaning code.
