# SHULL OS local app

API credits: the local tracker starts at the user-supplied $5 balance. New agent responses record an estimated USD charge from returned input/output/cache tokens, even when output validation fails. Missing usage is marked unknown. The ledger is persisted and deduplicated by run/step. Settings can reconcile to a new actual balance without charging old entries twice. Prior task estimates are informational and are not deducted from the new baseline. Pricing is standard global Messages pricing verified 2026-09-10 at https://platform.claude.com/docs/en/about-claude/pricing. Unknown models are unpriced, not free. Document preflight uses source-text length and modeled output sizes across nine possible agent calls (draft and one build review); it is a planning range, not a quote or spending limit. External spending, taxes, discounts, and top-ups are not synced. API-key reconnection is required after a server restart.

Run with Node 22+: `npm start`, then open http://127.0.0.1:4317.

Set SHULL_PYTHON to a Python executable with the repository build dependencies installed. Set SHULL_SOFFICE to LibreOffice's executable for PDF previews. Configure an Anthropic API key in Settings and select a model; the key stays in server memory only. The app runs separate bounded Messages API sessions using all seven repository role definitions. This is an application orchestrator, not Claude Code or the Agent SDK: role frontmatter tools and Claude Code hooks do not run here. The host limits agents to supplied context and structured outputs; no model-generated shell commands or file paths are executed.

Daily focus, draft specs and run statuses persist in app/data (gitignored). Generated documents are local draft artifacts. Try repository example works without a key. The server listens only on loopback and rejects cross-origin writes. This is a single-user local app, not ready for public hosting.

Implemented: Today, Create, local Library, paper assignment log, Standards reader, key connection, model discovery, agent worksheet drafting, existing worksheet builder, PDF rendering and page/ink audit when configured, teacher approval, and the Agents activity page. Drafting runs Overseer → Researcher → Designer → independent Auditor. Content defects stop the workflow and return a revision brief from Overseer. The user can request revision from findings. Building invokes Auditor again with artifact-existence and print-audit evidence, then Librarian for a filing recommendation and Overseer for an incomplete task report. Separate keys, visual inspection, web retrieval, actual Drive filing, Classroom posting, schedules, encrypted persistent credentials, and cross-device hosting are not implemented. Teacher approval does not imply full automated QA or Drive filing. General Class context is not yet supported by agent drafting; course-specific templates are required.

Agents → Run repository health review executes five repository validators, then Janitor and Secretary to produce report-only findings and PENDING proposal drafts. No authoritative files are edited. Reports persist in app/data/reports/<run-id>/ and appear in each run’s review. Secretary drafts are local reports, not adopted governance records. Each stage records status, source paths, timestamps, and token usage. A normal successful draft uses four calls; build review adds three. Failures never automatically retry or spend additional credits. Restarting interrupts active jobs; the key must be reconnected. Repository examples do not invoke agents.

The Secretary inbox appears on Today and Agents. Researcher findings from drafting are delivered through a separate Secretary call; Get updates runs a course briefing from course decisions, current focus items, and recent task metadata. Suggestions persist with source-run links. Add to today creates one linked focus item, Archive is reversible, and Send to Librarian creates one explicit handoff with a saved response. Failed/interrupted handoffs can be retried by the user. Drive filing remains pending. Drafts with research findings now include an additional Secretary call.

Run `npm test` for validation, agent handoff, and suggestion lifecycle checks. Live Anthropic calls require your key and API credits. Restarted in-progress jobs are marked interrupted; there are no automatic billable retries.
